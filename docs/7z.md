# Inner archive and publication

Every public archive is a portable two-password bundle described in
[archive-recovery.md](archive-recovery.md). Its root contains exactly
`encrypted.7z` and `key`, protected by an Argon2id-derived outer password.
The following describes the inner archive and shared filesystem safeguards.

## Inner contents

The inner archive uses solid compression and encrypted contents and headers:
`-t7z -ms=on -mhe=on`. Its password is a random 32-byte secret encoded as 64
hexadecimal characters, supplied through a protected pipe. The typed outer and
embedded-key passwords never reach 7z.

The inner archive contains the ordinary document folder and `.docvault-7z.json`.
This metadata authenticates the root, complete file list, sizes, SHA-256 checksums,
permissions, precise file timestamps and supported macOS extended attributes with
an HMAC derived from the random secret. `.DS_Store` is included. Wrapper member
names are reserved only in the outer archive; documents named `key` and
`encrypted.7z` remain ordinary documents inside the inner folder.

## Local key and privileges

The default `/usr/local/bin/key` is a root-owned encrypted regular file, mode 600,
without an ACL. Root-owned launchers invoke a standard-library-only sudo helper.
For fresh encryption, the helper validates and opens the encrypted local key,
then permanently drops real and effective UID/GID and supplementary groups before
loading project code, deriving passwords or running 7z. The worker consumes and
closes the key descriptor before starting any 7z process.

Decryption, verification, bundle password changes and updates of existing bundles
drop privileges without opening or requiring the local key. They unlock the
bundle's own embedded envelope. Neither recovery nor transfer imports or replaces
another machine's key. Custom installations support user-owned private local keys
without sudo.

For local `init` and `passwd`, an unprivileged worker derives and wraps the secret.
A root parent accepts only bounded, structurally validated encrypted key bytes,
serializes key writes with a stable lock, and acknowledges publication only after
flushing the replacement and its parent directory. Plaintext passwords and the
unwrapped secret never reach the privileged writer.

The local password and a random 16-byte salt feed Argon2id. Default costs are
3 passes and 256 MiB; `interactive` uses 2 passes and 64 MiB, and `sensitive` uses
4 passes and 1 GiB. XChaCha20-Poly1305 protects the random secret and authenticates
the envelope identity and cost settings. The embedded copy uses at least default
costs, with its own random salt, nonce and envelope ID. Local password changes
preserve the archive secret and affect only the machine-local file.

## Creation and update

Before fresh encryption, `encrypt.sh` asks for optional envelope/key and outer 7z
password hint groups. The name is `<folder-name>__<key-hint>__<7z-hint>.7z`, or
`<folder-name>.7z` when both hints are empty. Hints are public filename text and
are shown before password entry on decryption, verification and updates.
Without a path, the bundle is written inside `$PWD` and the current directory's
inode is retained. With another folder's path, it writes a sibling bundle. Only
the generated root-level bundle is excluded; other archives remain documents.
Automatic lookup supports both naming formats and refuses multiple matches.
All updates preserve the filename, two-layer format and bundle credentials.

Every operation shares a per-archive lock in a private `.docvault-archive-locks`
directory beside the output, or beside the document root for current-directory
bundles. Locks are independent of local-key availability and `--key` selection.

Creation scans the full source, moves it into private sibling staging (or reads it
in place for current-directory operations), rechecks identity and contents, builds
the inner archive, and independently extracts and verifies it. It builds the outer
bundle, reopens it through the production reader, and verifies the embedded key
and complete inner archive before publishing.

After source validation and before running 7z, encryption removes unsupported
`com.apple.metadata:*` extended attributes from the root, nested folders and files.
Each removal is reported and applies to retained plaintext with `--keep` too.
Supported attributes, including Finder tags, download information and Time Machine
exclusions, are preserved. Read-only scans, verification and decryption never
perform this cleanup. Failure to remove an attribute stops creation and retains
plaintext; attributes already removed are not restored if a later step fails.

The candidate is mode 600 without an inherited ACL. F_FULLFSYNC flushes it before
an exclusive rename for new outputs or atomic replacement for verified existing
outputs. The parent directory is flushed before any plaintext cleanup. Failure
after replacement reports uncertain publication and retains plaintext and staging.
Cleanup rechecks each file's checksum and identity and removes exactly the scanned
files and directories. Unexpected files stop cleanup. Failed operations retain
useful staging and report its location; candidates must be verified before reuse.

## Verification and restoration

The outer input is frozen through a non-following open of a bounded regular file.
Bounded binary header inspection establishes encrypted headers. Listing validation
requires exactly two regular, encrypted Copy members without solid compression.
Each allowed member is streamed into a bounded private mode 600 file. The strict
embedded envelope binds the exact inner digest and size; its password authenticates
and unlocks the secret. Verification never recursively unwraps the inner archive.

Inner verification freezes the ciphertext, validates paths and sizes, tests and
extracts it, authenticates metadata, checks every checksum, restores metadata and
rescans the resulting tree. Restoration flushes the verified tree and publishes
with exclusive moves. An existing destination is refused. Current-directory
restoration requires that the only existing child be its bundle and restores
beside it, retaining the directory inode and encrypted bundle.

Scratch directories are mode 700, checked for inherited ACLs, and excluded from
Time Machine before plaintext is written. Paths with traversal, control characters,
backslashes, colons or case-insensitive collisions are refused. Symlinks, hard
links, special objects, ACLs, resource forks and other unsupported attributes are refused.
File, total-size, parser, subprocess and disk-space limits bound processing.
macOS metadata and durability primitives remain required. Deletion is not secure
erasure, and plaintext is accessible while editing.
